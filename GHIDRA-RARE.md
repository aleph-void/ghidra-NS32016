# NS32016 / NS32532: Ghidra-Rare verification notes

SLEIGH module for National Semiconductor's Series 32000 (NS32016/NS32032, NS32532) with the NS32081 and
NS32381 FPUs and the NS32082 and on-chip MMUs. Imported from
[raybellis/ghidra-NS32016](https://github.com/raybellis/ghidra-NS32016) (Apache-2.0, commit
`f11d87c`), then rewritten and verified to the bar in the Ghidra-Rare `docs/VERIFICATION.md`.
Provenance and credits: [CREDITS.md](CREDITS.md). Builds for Ghidra 12.1.3, 12.1.4 and 12.2.

## What it covers

| Language id | CPU model |
|---|---|
| `NS32016:LE:32:default` | NS32016 with NS32081 FPU (a double uses an even/odd F pair) and NS32082 MMU registers (`BPR0/1 PF0/1 SC MSR BCNT PTB0/1 EIA`) |
| `NS32016:LE:32:NS32532` | NS32532 with NS32381 FPU (L0-L7 are independent 64-bit registers, Fn is the low half of Ln), the extra processor registers (`DCR BPC DSR CAR USP CFG`), the on-chip MMU registers (`MCR MSR TEAR PTB0/1 IVAR0/1`), PSR.V, `CINV`, and the NS32381 `POLY/DOT/SCALB/LOGB` |

Both share one instruction set: formats 0-9, 11 and 14, every general addressing mode (register, register
relative, memory relative through FP/SP/SB, external, absolute, immediate, TOS, PC relative, scaled index
B/W/D/Q), string and block instructions, bit and bit-field instructions, packed decimal, module calls,
the FPU and the MMU/processor register moves. `SP` is the live stack pointer; `SPB` is the other one and is
swapped with it whenever `PSR.S` changes (`LPR/BIS/BIC/RETT`), so SP-relative code always sees the right
stack. PSR flags are separate byte registers (`C T L F Z N U S P I`, `V` on the NS32532).

The `.slaspec` files are generated by `tools/gen_ns32016.py` (`gen_ns32016.py default|532`); the test
suite checks that the checked-in files are the generator's output.

An a.out loader (`NS32kAoutLoader`) imports linked NetBSD/pc532 executables and shared libraries
(OMAGIC/NMAGIC/ZMAGIC/QMAGIC, machine id 137) with their symbols as the NS32532 variant. There is no ELF
opinion and no `.dwarf` mapping: neither binutils nor any compiler for this family ever produced ELF or
DWARF (BFD's ns32k back end is a.out only; GCC used stabs).

## Known gaps

Doesn't work (each with its reason):

- **Hardware operations are pcodeops**, not p-code: `SVC`, `BPT`, `FLAG` (when F is set), `WAIT`, the
  divide-by-zero and privileged-instruction traps, `RETI`'s end-of-interrupt cycle, `RDVAL`/`WRVAL`
  (MMU probe, result in F), `CINV` and the `IVAR0/1` TLB purges, and the NS32381 `POLY`, `DOT`, `SCALB`,
  `LOGB`. Trap entry reads vector tables through `INTBASE` and an interrupt controller; cache, TLB and
  bus cycles are hardware state Ghidra cannot model. For `POLY/DOT/SCALB/LOGB` there is also no
  documentation here and MAME does not implement them, so their effects are unverified.
- **IEEE exception flags, trap types and the rounding mode in FSR** are not updated or honoured: p-code
  float operations round to nearest even and have no status. `LFSR`/`SFSR` only move the register.
- **Interrupts and trace traps** (`PSR.T/P/I`) are never raised: external events.
- The NS32016's 24-bit address bus is not modelled; addresses are 32 bits.
- **Ghidra limitation (not the module):** Ghidra caches instruction prototypes under a 32-bit CRC of the
  constructor tree and trusts it to be unique (`SleighLanguage.instructProtoMap`). The decode space here
  (about 80,000 distinct trees per variant when every addressing-mode pair is enumerated) makes CRC
  collisions certain in the exhaustive corpora, where a colliding instruction is decoded with another's
  prototype; the test harness clears the cache after every slot. A real program uses a few thousand
  distinct trees, so the chance of one collision is of the order of a percent per program.
- libm.so's two decompiler failures (`Overlapping input varnodes`) are in functions whose entry is a bad
  disassembly; a decompiler limit.

Unverified (no test covered it):

- Semantics against real hardware: there is no ns32k emulator or board available; the reference for
  flags and operations is the MAME core (source reading), whose own corner cases are listed below.
- Choices where the databook was not at hand: `ROUNDfi` ties to even (MAME), `CMPf` sets N only for
  src1 > src2, `DIVi` rounds toward minus infinity (MAME gives 0 for quotients in (-1,0)), `CHECKi` always
  writes its register, `INDEXi`/packed-decimal details ("TODO: CHECK" in MAME), `TOS` evaluated in operand
  order (an SP-relative second operand sees SP after the first operand's pop), unaligned accesses.
- The NS32381 register aliasing used by the NS32532 variant (Fn = low half of Ln, GCC's model). MAME's
  NS32381 model maps odd F registers to the high half of the preceding even L register instead.
- NS32532 specifics beyond the registers and CINV (cache and debug unit behaviour), `SETCFG` extra bits.
- Other CPU variants (NS32008, NS32032 differences are bus width only; NS32332, NS32CG16 bit-blt
  instructions are not decoded).

## Differences from the reference disassemblers (all classified by `test/compare.py`)

binutils decodes and the module deliberately does not:

- reserved addressing mode 0x13; an immediate or index as the base of a scaled index; an immediate as a
  written, address or Scc operand; a register in an address operand; odd registers for doubles on the
  NS32081; nonzero reserved bits in string/SETCFG option fields ("undefined" in binutils' output); NS32532
  and NS32381 instructions and registers in the default variant.
- binutils and MAME decode encodings with the invalid size code 2 (or `ADDR`/`JUMP`/`JSR`/`CXPD`/`CVTP`
  with a size other than D, `BICPSR/BISPSR` with D) that neither the module nor binutils accept (MAME
  validates nothing).

## Reference-tool bugs found

GNU binutils 2.45:
- `@disp` (absolute mode) is printed as an address made from the decimal digits of the displacement read
  as hexadecimal (`@0x4660` for displacement 4660 = 0x1234).
- `cxp` prints its link-table index as a code address.
- 19-bit opcode ids (`lfsr`, `rdval`, `wrval`) are compared on only 16 bits, so reserved gen2 bits are ignored.
- `sfsr` with a scaled index mis-reads the index byte (operand type `f` subtracts 5 bits twice).
- GAS for ns32k: `$` before an immediate is taken as a symbol (immediates are written without a prefix);
  BFD's ns32k configuration is marked removed in 2.45 and had to be re-enabled to build `gas`/`ld`.
- binutils prints the base register of an indexed float operand as `fN`.

MAME (`unidasm -arch ns32000`):
- 8-byte immediates print their low dword as `FFFFFFFF`.
- `MOVM`/`CMPM` lengths with a negative displacement are divided as unsigned.
- `SFSR` also decodes the unused first general-operand field, consuming extension bytes.
- Suspected, not confirmed: NS32081 `CMPf` sets N when src1 == src2, `DIVi` floor rounding for results in
  (-1,0).

## Running the tests

    GHIDRA_INSTALL_DIR=<scratch Ghidra 12.1.x> test/run-tests.sh [workdir] [--real]

See the header of `test/run-tests.sh` for the tools it needs (a binutils with the ns32k target for
`libopcodes`/`dumpopc`, optionally MAME `unidasm` and a binutils built for ns32k-netbsd to rebuild the
emulator programs; without the latter the committed `test/golden/` programs are used). `--real` downloads
the pinned NetBSD sets (SHA-256 checked) and runs `test/real-binaries.sh`.
